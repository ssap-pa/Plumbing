# 네이버 설비 블로그 게시글 작성

## 참고 파일 (작성 전에 읽는다)
- `templates/post-structure-analysis.md` : 두 블로그의 블록 순서·수치 근거
- `templates/f1house-style-template.md` : 에프원 스타일 블록 구조, 수치 목표, 고정 문구, 태그 규칙
- `templates/b1storage-style-template.md` : 비원 스타일 블록 구조, 수치 목표, 소제목·해시태그 규칙
- `templates/post-input-form.md` : 사용자 입력 양식과 출력 형식
- `research/ansan-blog-operating-plan.md` : 상호·전화번호·시공 지역·카테고리 (확정값이 있으면 이 파일을 따른다)

## 절차
1. 입력에서 스타일을 확인한다. 지정이 없으면 **에프원 스타일**을 기본으로 쓴다(지도가 첫 사진 앞, 마무리에 전화번호 포함).
2. 입력 양식의 빈 항목은 묻지 않고 비운 채 작성하되, 결과 끝에 "확인 필요" 목록으로 표시한다(건물 정식 명칭, 자재명, 수치 등).
3. 사진을 공정 단위로 묶는다. 에프원 4묶음(3~5), 비원 8~10묶음. 마지막 묶음은 항상 "시공 완료".
4. 템플릿의 블록 순서를 그대로 따라 작성한다. 지도 위치, 구분선 수, 스티커 수, 첫·마지막 글 블록 길이를 수치 목표 범위 안에 맞춘다.
5. 키워드 반복 횟수를 맞춘다.
   - 업체명: 에프원 4~5회 / 비원 3회
   - 현장 지역명(시+동): 3~7회. 첫 블록, 공정 글 1곳 이상, 마무리에 각각 포함
   - 주 작업 키워드(제목의 핵심 작업명): 7회 이상
   - "문의" 또는 "연락": 에프원 3회 / 비원 1~2회
6. 제목은 템플릿 공식으로 만들고 길이를 확인한다(에프원 40~50자, 비원 50~60자).
7. 태그를 만든다(에프원 18~22개, 비원 30개). 1~2번째는 상호. 지역×작업 조합을 절반 이상 넣는다.
8. 출력 형식(`post-input-form.md`의 "출력물")대로 블록 마커를 붙여 돌려준다. 사진은 입력의 파일 번호로 지정한다.
9. 마지막에 자체 점검표를 붙인다: 글자 수, 글 블록 수, 사진 묶음 수, 지도 위치, 업체명·지역명·작업 키워드 횟수, 태그 수.

## 금지
- 입력에 없는 수치·자재명·고객 발언을 만들어 넣지 않는다. 필요하면 `{확인: ...}` 자리표시로 남긴다.
- 동·호수, 고객 이름, 노출 제외 요청 항목은 쓰지 않는다.
- 다른 업체명(에프원하우스, 비원스토리지)과 그 전화번호·슬로건은 결과물에 넣지 않는다.
